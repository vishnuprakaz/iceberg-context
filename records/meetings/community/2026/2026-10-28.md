## Derived (generated) columns proposal

Szehon presented the RFC, written with a co-author from the Presto community, for columns whose value is always a deterministic expression over other columns of the same table, building on the expressions spec. Unlike default value expressions, the value is guaranteed and may reference other columns, which enables filter inference, avoiding recomputation and stats-based pruning. Each schema field would get an optional generated object holding the expression and a stored flag; for V4 the proposal is to allow only stored columns so readers need no changes, leaving virtual columns for later, and an optional list of valid generated column ids in the snapshot was described as a guard against writers that do not maintain the values. Determinism of UDFs can rely on the flag in the UDF spec. It was also mentioned that the feature could land in the index spec first, for example for Hilbert curve values. The request was for comments on the document.

**Open questions:**
- Will derived columns make V4, or land first in the index spec and in the table spec later?
- Is the valid generated column ids list in the snapshot needed?
- Can collations be expressed with derived columns, and what else would they need?
