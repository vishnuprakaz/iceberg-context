## Spark versioning going forward

The discussion followed the dev list thread on Spark versioning strategy with accelerated Spark releases. The points listed are a policy of one LTS plus two minors (at most three Spark versions), whether that means 3.5, 4.1 and 4.2 with 4.0 removed, and what to follow going forward while keeping the CI burden in mind. The notes pose these as questions and record no decision.

**Open questions:**

## CI usage

Parallel Spark test execution merged on May 18, splitting the Spark matrix into concurrent core and extensions jobs and cutting the run from about 84 to 58 minutes. A single Gradle cache writer stops about ten jobs racing to write overlapping caches against the 10 GB cap. In flight are a PR reducing TestRewriteDataFilesAction data volume and one selecting PR matrices incrementally from changed files, with Java 17 as the primary PR JVM and full coverage on main, release and tags. The group also asked whether some tests could use in-memory FileIO, perhaps by switching the default FileIO to see if anything breaks.

**Open questions:**
- Can in-memory FileIO be used for some tests, for example by switching the default FileIO to see what breaks?
