## Limit scope to a single layout and full key lookup

A recommendation from offline discussions is to limit the scope to a single layout and a single use case, full key lookup, to prevent scope creep. The index would have a specific depth requirement and performance guarantee for only a single transform, and getting that performance requires the full key and knowing how to implement the transform used before sorting. The notes present this as a recommendation, not a recorded decision.

## Index history handling

The notes repeat that most database systems treat index changes as drop-and-recreate, so keeping index metadata history has little value. Under that approach maintenance creates a new metadata.json and swaps it in atomically, and the catalog cleans up obsolete metadata and index data files per its retention policy.
