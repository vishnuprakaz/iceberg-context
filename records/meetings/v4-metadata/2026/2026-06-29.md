## Avoiding the old-manifest scan on data DV updates

Even with a manifest DV, a data DV update still needs to scan the old manifest file to fetch the old entry (for example its content_stats) in order to produce the new manifest entry. If the client carried content_stats from scan planning to commit, that overhead could potentially be avoided. The notes observe that FileScanTask contains DataFile, DeleteFile and List<ColumnFile>, and list API ideas: a new add(TrackedFile) with TrackedFile exposed as a public interface, or expanding DeleteFile with DataFile colocatedDataFile() plus List<ColumnFile> columnFiles(), since the former alone would not cover column files.
