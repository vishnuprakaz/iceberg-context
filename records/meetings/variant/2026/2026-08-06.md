## New shredding algorithm: 'uniform'

The earlier majority-based algorithm could create mixed-type columns (for example int and string), which degrades read performance. The notes say the 'uniform' algorithm was chosen after benchmarking because it manages reader cost better: a field is admitted for shredding only if all non-null values in the sample buffer (the first 100 rows) belong to a single type family. This keeps shredded columns homogeneous. The PR is under community review. The July sync notes had named the Wilson strategy as the leading candidate.

**Decisions:**
- The 'uniform' shredding algorithm was selected: a field is shredded only if its sampled non-null values are from a single type family.

## Cross-implementation alignment and testing

The goal is consistent variant behavior across all Iceberg implementations, with the nearly complete Go implementation as the reference for Rust and C++ ports. A shared test suite is being developed; the proposed test uses a well-defined JSON/BSON object to see how mixed types are shredded, since the physical Parquet representation reveals which algorithm was used. Known pitfalls for new implementations are decimal precision, which needed several fixes, and reading multiple shredded columns, where a past bug was fixed.
